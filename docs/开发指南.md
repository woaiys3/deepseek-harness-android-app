## 一、项目简介

把 **DeepSeek Harness（DSH）** 打包成可安装到 Android 手机的 App：

- **内核**：DeepSeek Harness（`@deepseek-ai/dsh` 0.1.5-rc.1，子包解析到 0.1.5-rc.2），保留插件生态 + RPC API。
- **前端**：DSH 原生界面（`dsh-web-frontend` dist），只做移动端适配，不自研页面。
- **移动端适配**：自由旋转（竖屏/横屏）+ 触摸优化 CSS（`mobile-patch/mobile.css`）+ 软键盘适配 + 窄屏侧栏改造（三条杠 + 浮层侧栏，v1.3.0 起改核心源码）。
- **手机端特色**：Shizuku 特权插件 + 系统能力插件 + **原生权限引导页**（9 项权限一站式配置）。
- **品牌**：DeepSeek Harness，鲸鱼图标。
- **包名**：`com.deepseek.harness`

### 项目原则

1. **页面 = DSH 原生界面 + 移动端适配**：功能全保留，不做自研页面替代。
2. **API Key 不写文件、不打包进 APK**：凭证由使用者在页面里填写，只存本机。
3. **签名密钥（release.jks）不入仓库**：由维护者离线保管。
4. 自由旋转（竖屏/横屏）；品牌只与 DeepSeek Harness 相关。

## 四、架构

```
APK (com.deepseek.harness)
├── MainActivity（原生壳）
│   ├── 【权限引导页】首次启动（"首次使用 · 配置手机权限"）
│   │   ├── 9 项权限行：存储/所有文件/悬浮窗/写设置/使用情况/
│   │   │             安装未知来源/电池优化/通知/Shizuku
│   │   └── 「开始使用」按钮：写入 setup_done → 进加载页并解压运行时
│   ├── 【加载页】鲸鱼 logo + 品牌名 + 状态文字 + 进度条（启动完成进引擎页）
│   ├── 【引擎页】WebView 加载 http://127.0.0.1:3080（DSH 原生界面）
│   ├── 解压 assets/payload.zip
│   │   ├── dshroot → /sdcard/DeepSeekHarness/dshroot（外部，已有文件不覆盖，
│   │   │           白名单 FORCE_OVERWRITE_PREFIXES 强制覆盖 shizuku 插件）
│   │   └── runtime/dshhome/bin → 内部 files/payload/
│   ├── 重建 runtime/lib 软链（LINKS.txt，link→symlink→copy 三级降级）
│   └── 拉起 node --expose-internals dsh/lib/bin.js web --host 127.0.0.1 --port 3080
└── 前端 = DSH 原生 dist，通过 DSH /api 通信
```

### 启动流程

1. `onCreate`：若 `setup_done` 已写入 → 直接 `showEngineScreen()` + `startEngine()`
2. 首次启动 → `showPermissionScreen()`（权限引导页），点「开始使用」后写 `setup_done` → 进加载页
3. `startEngine()`：解压/补齐 payload（REVISION 判断，白名单强制覆盖 shizuku 插件）→ 按 LINKS.txt 重建 runtime/lib 软链 → `node --expose-internals bin.js web --host 127.0.0.1 --port 3080`
4. 全局崩溃 handler 自动写 `/sdcard/DeepSeekHarness/crash.log`

### Shizuku 插件（dsh-tool-shizuku，三层修复）

- **异步 `spawn`**（不是 spawnSync，避免阻塞 node 事件循环 → 曾导致 "Failed to fetch" 的根因）
- `sanitizeEnv()`：剥离 `LD_LIBRARY_PATH/LD_PRELOAD/LD_DEBUG`（避免 app_process 链接错 libz.so）
- `ensureDexReadOnly()`：每次执行前 `chmod 444`（Android 15 拒绝加载可写 dex）
- 默认**自动执行**，设 `SHIZUKU_APPROVE=ask` 才逐次审批

## 五、DSH API 协议速查

**通用 RPC**（POST /api/<method>）：

```json
{"type":"client-request","rpcId":"<uuid>","method":"session.prompt","payload":{...}}
```

返回：`{"type":"server-response","rpcId":"...","result":{"ok":true,"value":{...}}}`

**关键方法**：

| 方法 | 说明 |
|---|---|
| `session.create` | 建会话 |
| `session.list` | 会话列表 |
| `session.history` | 拉历史 `{sessionId, maxMessages}` |
| `session.prompt` | 发消息 `{sessionId, mode:"queue", content:[{type:"text",text}]}` |
| `session.models` / `session.selectModel` | 模型列表/切换 |
| `credentials.set` / `credentials.describe` | API Key |
| `workspace.archiveSession` | 归档会话 `{sessionId}` |

**收流式**：WebSocket `ws://127.0.0.1:3080/api/events.mux`，关键事件：

- `turn/start`、`assistant/chunk`（reasoning-delta/text-delta/usage/finish）、`tool/code-dispatch`、`session/title`

## 七、注意事项（踩坑记录）

1. **⚠️ targetSdk 必须保持 28**：`targetSdk ≥ 29` 时 Android 把应用私有数据目录挂 noexec，node 二进制执行报 EACCES（`error=13, Permission denied`）。除非做 nativeLibraryDir 迁移，否则别动 targetSdk。
2. **node 运行需 `LD_LIBRARY_PATH=runtime/lib`**。
3. **Android 无 `/usr/bin/env`**，wrapper 脚本 shebang 用 `#!/system/bin/sh`。
4. **DSH 启动必须加 `--expose-internals`**。
5. **Android SELinux 禁硬链接 `link()`**，原子写用 `rename()`。
6. **runtime/lib 有软链**，APK 只打实体文件 + `LINKS.txt`，App 首次启动重建。
7. **`pkill -f` 会误杀自己**，用 `pkill -x node`。
8. **Shizuku `pm install` 在 ColorOS 报 binder 限制**，安装靠用户手动点 APK；`pm clear/uninstall` 可用。
9. **npm/pnpm 是开发工具，不进 APK**。
10. **API Key 绝不写文件/APK**，用户通过页面设置填。
11. **DSH 更新会覆盖补丁和前端**，更新后跑 `apply.sh` + `build.sh`。
12. **⚠️ 原生 View 重复挂载崩溃**：`webView/statusView/progressBar` 是成员视图，界面切换（如 `showEngineScreen()`）都要先 `detachView()` 再 addView，否则 "child already has a parent" 崩。新增视图时沿用 `detachView()`。
13. **⚠️ Shizuku 回调在 binder 线程**：`onBinderDead` 等回调里更新 UI 必须 `post` 回主线程，`refreshAllStatuses()` 已内置线程保护。
14. **⚠️ 不要用 `spawnSync` 执行耗时命令**：会阻塞 node 事件循环 → 后端假死 → 前端 "Failed to fetch"。用异步 `spawn`。
15. **⚠️ ColorOS 电池优化会切断 Shizuku 连接**：建议把 DeepSeek Harness 和 Shizuku 都设"不限制"，否则 Shizuku 通道会断。
16. **dshroot 外部更新策略**：`FORCE_OVERWRITE_PREFIXES` 白名单强制覆盖随 APK 更新的官方路径（当前 5 项：dsh-tool-shizuku、dsh-tool-android 两个插件目录 + `dsh-web-frontend/dist/` 的 mobile.css/mobile.js/index.html + dsh 的 package.json），其余已有文件不覆盖（保留运行时修改）。

## 八、插件开发路径

插件 = npm 包，核心 `ctx.tools.register(defineTool({...}))`，注册三步：

1. 包放 `dshroot/lib/node_modules/@deepseek-ai/dsh/node_modules/@deepseek-ai/<名>/`
2. 在 dsh 的 `package.json` dependencies 加包名
3. 在 `$DSH_HOME/cordis.patch.yml` 的 `insert:` 加 `- id: <名> name: '@deepseek-ai/<名>'`
4. 归档到 `dsh-patches/overlay/`，更新 `apply.sh`

Shizuku 调用（已验证）：

```sh
DEX=/data/user/0/com.deepseek.harness/files/rish/rish_shizuku.dex
/system/bin/app_process -Djava.class.path="$DEX" /system/bin --nice-name=rish \
  rikka.shizuku.shell.ShizukuShellLoader -c "<命令>"
```

环境变量 `RISH_APPLICATION_ID=com.deepseek.harness`。

> DSH 自带 bash 工具已 shim 到 /system/bin/sh，文件工具 fs 已可用；缺的是 Shizuku 特权层（已有 dsh-tool-shizuku）和更多系统能力插件。

## 九、Shell 权限实测（无 root，Shizuku shell 模式）

DSH 通过 `shizuku_shell` 实测（uid=2000, u:r:shell:s0）：

✅ **能**：读 /system /vendor、读写 /data/local/tmp、读写 /sdcard、pm/am/settings/dumpsys、input、screencap

❌ **不能**：读其他 App 私有数据（/data/user/0/*）、读 /data/system（packages.xml）、改 /system 分区、真正 root 全文件访问

要全文件访问只有 root（Magisk）或 userdebug 固件；量产机（ro.debuggable=0、无 su）的上限就是 shell。
